# 环境与依赖审查方法

## 为什么

在引入外部依赖（[[lark-openapi-mcp]]、[[llm-wiki]]）之前，先以**只读**方式确认本机环境是否满足前置要求、依赖的能力边界是否覆盖方案需求，避免在安装与配置之后才发现硬伤。只读检查不改变系统状态，可安全重复执行。

## 怎么做

1. **清点环境**：记录系统版本、磁盘余量、网络可达性、运行时版本（Node.js / npm、Python、git）、已有 MCP 配置。
2. **逐项核对 README**：把每个依赖的许可证、状态（如 Beta）、安装方式、运行命令、鉴权模式、工具范围与**明确限制**原文摘录。
3. **区分事实与推论**：README 原文为高证据强度；基于限制推导出的可行性判断标注为推论，需实测确认。
4. **记录待决策项**：把需要用户提供或决定的事项（应用创建、许可证接受、模型选择、安装位置、数据导出方式）显式列出。
5. **标注安全实践**：如密钥经环境变量注入，不写入命令参数或项目文件。

## 适用场景

可复用于后续阶段（阶段 B 飞书集成、阶段 C LLM Wiki 部署、阶段 D 数据管道）的前置核查。
