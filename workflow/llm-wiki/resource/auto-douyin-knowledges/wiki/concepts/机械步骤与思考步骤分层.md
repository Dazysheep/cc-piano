# 机械步骤与思考步骤分层

## 定义

「机械步骤与思考步骤分层」是抖音运营自动化方案中的核心架构原则：把每日流水线拆成两类步骤，分别用不同执行器承担。

- **机械步骤**：抓数据、渲染视频、打开发布页、发飞书消息等确定性操作，用**普通 Python 脚本**执行，不消耗模型调用。
- **思考步骤**：写日报分析、写学习笔记、写周报内容、根据热词改标题与话题等需要判断的操作，以**非交互方式调用 Claude Code**（`claude -p "<提示词文件>"`）执行。

## 为什么这样分

1. **成本**：机械步骤占流水线绝大多数调用次数，用纯脚本可避免无谓的模型开销。
2. **稳定性**：渲染、上传、发消息这类操作结果确定，脚本行为可预测、易回归测试；交给 LLM 反而引入不确定性。
3. **可审计**：脚本日志能逐条核对；LLM 输出需要额外校验。
4. **权限边界**：思考步骤需要 LLM Wiki MCP、lark-cli、pptx 等技能，工具白名单化后可无人值守运行；机械步骤不需要这些能力，也就不必暴露。

## 具体划分（方案原文）

| 类别 | 步骤 | 执行器 |
|---|---|---|
| 机械 | 抓创作者中心数据（`fetch_creator.py`） | Python + Playwright |
| 机械 | 渲染竖屏成片（`build.py --prepare`） | Python |
| 机械 | 打开发布页并填表（`publisher.py --job`） | Python + Playwright |
| 机械 | 发飞书消息、上传文件、建文档（`notify.py`） | Python 调 lark-cli |
| 思考 | 写日报分析（`report.py` 中的分析段） | `claude -p` |
| 思考 | 写学习笔记（`learn/session.py`） | `claude -p` |
| 思考 | 写周报内容（`weekly/deck.py`） | `claude -p` |
| 思考 | 按热词改标题与话题（`publish_at.py`） | `claude -p` |

## 运行前提

- 计划任务以非交互方式调用 Claude Code，工作目录固定为 `D:\cc-engine`，以便使用 LLM Wiki MCP、lark-cli、pptx 等技能。
- 允许使用的工具在 `.claude/settings.json` 里白名单化，避免无人值守时卡在权限确认上。
- 这些时段电脑需开机并已登录 Windows（发布要弹出可见的 Edge 窗口），计划任务勾选「唤醒计算机运行」。

## 张力与风险

- **单点失败**：22:00 任务同时依赖 Claude 改标题与 Playwright 打开 Edge，两者串行且都需电脑唤醒并已登录，任一失败即整链失败。
- **边界模糊**：日报的「指标计算」属机械（复用 `analytics/report.py`），「改进建议」属思考，同一脚本内混用两类执行器，需在代码结构上明确切分。
- **降级路径**：学习环节若遇登录框或验证码，应停下记录并退回搜索引擎，而非让 LLM 自行绕过。

# 机械步骤与思考步骤分工

机械步骤与思考步骤分工是本方案的核心架构原则：把工作流拆成两类步骤，分别用不同技术手段执行，以降低模型调用成本并提高稳定性。

## 两类步骤

- **纯机械步骤**：抓数据、渲染、打开发布页、发飞书消息。用普通 Python 脚本实现，**不消耗模型调用**。
- **需要思考的步骤**：写日报分析、学习笔记、周报内容、改热点词。由计划任务以非交互方式调用 [[claude-code]]（`claude -p "<提示词文件>"`），工作目录 `D:\cc-engine`。

## 调度骨架

- 定时触发用 Windows 计划任务（`schtasks`），每个任务调用一个 Python 入口脚本，全部用 `douyin\.venv` 运行，日志写在 `workflow\logs\`。详见 [[windows计划任务]]。
- 前提：这些时段电脑要开着并已登录 Windows（发布要弹出可见的 Edge 窗口），计划任务需勾选「唤醒计算机运行」。

## 代码放置约定

- 抖音运营自动化放在 `workflow/`。
- 视频制作的改动放在 `douyin/tracks/` 和音轨剪辑页面。
- 通用的飞书通知封装成 `workflow/notify.py`。
