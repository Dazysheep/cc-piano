# 模板库版本化

模板库版本化是 cc-piano 音轨剪辑视频生产中的一项结构性改造：把「怎么做视频」与「做哪首歌」彻底分离，并让「怎么做」以带版本号、永不覆盖的方式沉淀下来。它既是工程上的配置管理方案，也是抖音运营实验得以归因的前提。

## 问题背景

改造前的 cc-piano 没有模板库。每首歌对应一个 json 文件，保存时由 `save_track_song`（`server.py:273-291`）直接覆盖，没有任何版本记录。这意味着：

- 视频的视觉与节奏参数（主题、效果、方向、钩子、片段长度）与歌曲数据混在同一份文件里，无法复用；
- 每次调整参数都会覆盖旧配置，无法回退，也无法对比「改之前」和「改之后」的出片差异；
- 运营实验缺少可对照的基线，无法判断完播率变化究竟来自哪一版改动。

## 设计

### 目录与命名

模板存放在 `tracks/templates/<模板名>/v<N>.json`，例如：

- `daw-classic@v1` —— 现有效果整理而成的基线版本；
- `daw-hook@v2` —— 第一轮实验版本。

命名采用 `<模板名>@v<N>` 形式，版本号单调递增。

### 职责分离

- **模板 json 只存「怎么做」**：主题、特效、是否竖屏、钩子参数（`cold_open`、`intro`、`fade_in`、`hook_text`、转场时长）、片段长度、淡入淡出拍数等。
- **歌曲 json 只存「做哪首」**：音频、LRC、标题、发布信息等。
- **引用方式**：歌曲 json 通过 `"template": "daw-classic@v1"` 指向模板。
- **优先级**：歌曲自身字段优先于模板字段，允许对单首歌做局部覆盖。

### 永不覆盖原则

每次实验优化都存成新版本（v2、v3……），旧版本永远不覆盖。这样任何一版出片都可以被精确复现，历史数据也始终能对应到产生它的那版配置。

### 界面能力

音轨剪辑页面新增三项能力：

1. 「模板」下拉框，选择当前使用的模板版本；
2. 「另存为新版本」，把当前参数固化为新的 `v<N>`；
3. 「用这个模板批量生成」，选多首歌后进入同一个任务队列（复用 [[concepts/任务队列与子进程进度协议]]）。

## 与实验设计的关系

模板库版本化直接服务于 [[methodology/单变量短视频实验法]]：

- 基线 `daw-classic@v1` 保证旧歌出片完全一致，可用 `unhappy.json` 做逐帧回归对比；
- 实验版本 `daw-hook@v2` 在 v1 基础上叠加竖屏、直接进副歌、第一帧有声、0–3 秒钩子文字、缩短拨片开头等改动；
- 每版模板对应一段 2–3 天的观察窗口，用完播率与 2 秒跳出率对比。

需要注意的张力：v2 一次性引入了多个变量，与「一次只改一个变量」原则存在冲突，归因能力因此被削弱。模板版本化本身提供了解决路径——后续可把 v2 拆成多个只差一个变量的版本（如仅竖屏、仅钩子），逐一对比。

## 验证要点

- 用 `unhappy.json` 分别以 `daw-classic@v1` 和旧代码出片，逐帧对比，确认旧模板结果不变；
- `daw-hook@v2` 出竖屏 10 秒预览，用 ffprobe 检查分辨率为 1080×1920，并抽第 0、1、3 秒画面确认钩子生效；
- 用一段真实 iPhone 录屏从收件箱走完整条流程，确认模板引用与字段优先级按预期工作。
