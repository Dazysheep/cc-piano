# 定时任务编排与登录态依赖

## 是什么

定时任务编排指把一条内容生产与运营流程拆成若干按日/周节律触发的任务，交给操作系统调度器（此处为 [[windows计划任务]]）执行。**登录态依赖**是其中一种架构选择：任务只在用户已登录的桌面会话中运行，因为某些步骤需要打开可见的浏览器窗口（如 Edge 发布页），无法在无会话的后台服务中完成。

## 在 cc-piano 中的落地

cc-piano 的「cc-piano」任务文件夹（2026-10-25 开启）包含四个任务，形成日/周闭环：

| 任务 | 时间 | 职责 |
|---|---|---|
| daily-report | 每天 12:00 | 读创作者中心 → 日报发飞书群 + 存档 + 写知识库 |
| daily-make | 每天 14:00 | 收新录屏 → 认歌 → Claude 写评论故事/开头评论/文案 → 检查 → daw@v6 出片 → 发群审核 |
| daily-publish | 每天 21:58 | 随机 22:00–22:29 打开抖音发布页填好，飞书提醒，人工点发布 |
| weekly-ppt | 每周六 18:00 | 周报 PPT 发群 |

## 设计要点

- **按节律分工**：数据抓取（午间）、内容生产（午后）、发布（夜间）、周报（周末）各占一个时段，互不抢占资源。
- **登录态依赖的代价**：机器未登录或休眠时任务不执行，且本来源未说明失败告警机制，存在静默漏跑风险（见 [[定时任务漏跑如何告警]]）。
- **自动化不等于无人值守**：daily-make 出片后需群内审核，daily-publish 自动填表但由用户点发布，实质仍有人工闸门，见 [[发布台人工把关]]。
- **与思考/机械分层的关系**：定时任务承载机械步骤，把「写故事」这类思考步骤交给 Claude，见 [[机械步骤与思考步骤分层]]。
