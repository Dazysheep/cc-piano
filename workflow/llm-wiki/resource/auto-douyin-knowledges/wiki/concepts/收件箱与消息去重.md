# 收件箱与消息去重

收件箱与消息去重是方案中「用户把 iPhone 录屏发到飞书群 → 程序自动收取并制作」这一链路的实现机制。

## 收件箱

- 本地目录：`douyin/收件箱/`。
- `produce.py` 每天用 `lark-cli im +chat-messages-list` 找出「抖音运营」群里新的视频或音频消息，用 `+messages-resources-download` 下载到收件箱。
- 收件箱里的录屏会被识别曲名（复用 `tracks/cache_identify.py` 和 `tracks/song_ocr.py` 抽一帧做 OCR），然后生成歌曲 json。
- 收件箱空了，就从剪映缓存里列出最新的 3 首热曲发飞书让用户选，用户回复之前不渲染。

## 去重

- 处理过的 `message_id` 记在 `workflow/data/inbox_seen.json`，因此不会重复处理同一条消息。
- 处理完在群里回复「已收到，开始制作《曲名》」。

## 前提与阻塞

机器人当前没有读群消息的权限（实测报 230027），在用户重新授权前该链路不可用。详见 [[抖音运营]] 与 [[lark-cli]]。

# 收件箱模式（inbox）

收件箱模式是一种「素材先落到固定目录、程序按序消费」的输入设计：用户把录屏发到飞书群，程序把群里的新视频/音频消息下载到本地收件箱 `douyin/收件箱/`，再按顺序取用。它把人工投料与自动生产解耦。

## 工作方式

1. `produce.py` 每天用 `lark-cli im +chat-messages-list` 找出「抖音运营」群里新的视频或音频消息；
2. 用 `+messages-resources-download` 下载到 `douyin/收件箱/`；
3. 处理过的 message_id 记在 `workflow/data/inbox_seen.json`，所以不会重复处理；
4. 处理完在群里回复「已收到，开始制作《曲名》」；
5. 收件箱里的录屏会被识别曲名（复用 `tracks/cache_identify.py` 和 `tracks/song_ocr.py` 抽一帧做 OCR），然后生成歌曲 json。

## 空箱降级

收件箱空了，就列出剪映缓存里最新的 3 首热曲（`jianying_cache()` 的逻辑）发飞书让用户选，用户回复之前不渲染。

## 前提与风险

机器人现在没有读群消息的权限（实测报 230027），需用户身份或后台加权限。详见 [[机器人能否读取抖音运营群消息]]。
