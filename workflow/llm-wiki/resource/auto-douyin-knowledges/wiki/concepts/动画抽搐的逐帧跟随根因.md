# 动画抽搐的逐帧跟随根因与平滑参数

「动画抽搐」指 cc-piano 中 [[女生小人]] 唱歌时动作抖动、不自然的现象。其根因不是模型或渲染缺陷，而是**动画参数逐帧跟随原始信号**：每一帧都直接读取未经平滑的音量或节拍数据，导致动作在相邻帧之间剧烈跳变。修复思路是对信号做时间窗平滑，并固定会随信号变化的结构性元素。

## 四条成因

1. **嘴型**：每帧跟着原始音量变，音量抖动直接传导为嘴型抖动。
2. **踮脚**：在节拍点上瞬间跳起，缺少起落过渡。
3. **举手**：在音量阈值附近来回切，信号在阈值上下波动时动作反复切换。
4. **音符数量**：随音量变化，导致音符位置跳动。

## 六项平滑参数

| 部位 | 修复方式 |
|---|---|
| 嘴型 | 0.11 秒才换一次（音量取 ±0.08 秒平均） |
| 踮脚 | 用正弦慢慢起落 |
| 举手 | 用 0.4 秒一换的慢音量 |
| 音符 | 固定两个 |
| 副歌过渡 | 进出副歌时摇摆幅度 0.6 秒平滑过渡 |

## 可复用原则

- 任何由连续信号驱动的动画参数，都应先做时间窗平滑再驱动动作。
- 阈值型动作（举手）应使用慢速信号，避免在阈值附近抖动。
- 结构性元素（音符数量）应固定，不随信号变化。
- 段落切换（副歌进出）需要过渡时间窗，而非瞬时切换。

## 证据强度

机制解释合理，但来源未给出修复前后的帧级对比或观感评分，属未量化验证的修复。
