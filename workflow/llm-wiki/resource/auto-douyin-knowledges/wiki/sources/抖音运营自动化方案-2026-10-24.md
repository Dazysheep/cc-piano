# 抖音账号自动化工作流（cc-piano 音轨视频）实施计划

## 概述

这是一份面向抖音账号的自动化运营实施计划，主题为「音轨剪辑」视频：编曲软件风格的多轨画面，配像素风的 Claude Code 小人。触发背景是近期完播率仅约 1%。文档把「选曲 → 做视频 → 发布 → 看数据 → 学习 → 优化」设计为每日自动运转的流水线，并给出探查结论、总体架构、每日时间表、7 步实施计划、验证清单与用户配合事项。

视频生产端的主体是 [[cc-piano琴房-studio]]，模板库、竖屏改造、收件箱均落在其代码库内。通知与文件通道全部走飞书（[[lark-cli]]），结论同步到 [[llm-wiki]] 知识库。

## 用户已确认的选择

- 到点通知、用户当场检查后自己点「发布」（最终把关留给用户）。
- 通知用飞书，发到新建的内部群「抖音运营」（用户本人 + 机器人，可再拉同组织的人）。外部群「The First Step」因飞书跨组织限制报 230027，弃用。
- iPhone 录屏（1–2 分钟）直接发到「抖音运营」群（群 ID `oc_63d0c14e3f625b0076518dc23bc6f8dc`，记在 `workflow/config.json`）。
- 成片约 60 秒，从录屏里截一段，截取点对齐节拍并加淡入淡出，画面随节拍动，开头和转场卡在重拍上。
- 录屏只用声音，再抓一帧播放器画面做封面并识别曲名。
- 数据由程序自动读取创作者中心；学习用不登录的独立浏览器。
- 曲子来源是收件箱文件夹，收件箱空了从剪映热曲里挑（挑之前先问用户）。
- **允许直接修改音轨剪辑页面**（这一项解除了之前的保护要求）。
- 日报 12:00；周报周六 18:00。

## 探查结论（决定优先级）

1. **音轨视频只有横屏 1920×1080**（`tracks/daw.py:18`；`build.py:295` 把 `orientation` 写死成 horizontal）。抖音是竖屏刷的，横屏视频在手机上只占中间一小条，很可能是完播率低的头号原因。
2. **前 3 秒没有钩子**：开头是 4 秒拨片动画，再接 1.8 秒水墨转场（`daw.ENTRY`），音乐还要淡入 1 秒（`build.py:274`），人声最早在第 5 秒左右才出现。
3. **iPhone 录屏不能直接用**：上传接口只收音频格式（`web/server.py:45`）；`tracks/prepare.py:63` 本来就会先用 ffmpeg 转成 wav，所以支持 mp4/mov 改动很小（加 `-vn`）。
4. **没有模板库**：每首歌一个 json，保存时直接覆盖（`save_track_song`，`server.py:273-291`），没有版本。
5. **发布台**（`publish/publisher.py`）：用 [[playwright]] 打开 Edge（登录信息在 `publish/profile`），自动填标题、文案、最多 5 个话题和 AI 声明，停在「发布」按钮前。不会自动选封面，也没有定时发布。同一个 profile 同一时间只能被一个窗口占用。
6. **数据**：`analytics/report.py` 能读创作者中心导出的表，计算点赞率、互动率和综合分；现在没有任何真实数据，也没有读取创作者中心的代码。
7. **飞书**：lark-cli 已经以用户身份登录（应用 `cli_aa58…`），但还没有发消息的脚本，也没有定好发到哪个会话。PPT 可以复用 `ppt/` 里的 pptxgenjs（已安装）。
8. **定时**：现在没有任何定时任务代码。总方案定的是 [[windows计划任务]]，先手动跑稳几次再挂上去。

## 总体架构

- **定时触发**：Windows 计划任务（`schtasks`），每个任务调用一个 Python 入口脚本，全部用 `douyin\.venv` 运行，日志写在 `workflow\logs\`。
- **需要思考的步骤**（写日报分析、学习笔记、周报内容、改热点词）：计划任务以非交互方式调用 Claude Code（`claude -p "<提示词文件>"`），工作目录是 `D:\cc-engine`。允许使用的工具在 `.claude/settings.json` 里白名单化，避免无人值守时卡在权限确认上。详见 [[机械步骤与思考步骤分层]]。
- **纯机械的步骤**（抓数据、渲染、打开发布页、发飞书消息）：普通 Python 脚本，不消耗模型调用。
- **前提**：这些时段电脑要开着，并且已登录 Windows（发布要弹出可见的 Edge 窗口）。计划任务勾选「唤醒计算机运行」。
- 新代码放置：抖音运营自动化放在 `workflow/`（按 CLAUDE.md 约定）；视频制作的改动放在 `douyin/tracks/` 和音轨剪辑页面；通用的飞书通知封装成 `workflow/notify.py`。

### 每日时间表

| 时间 | 任务 | 入口 |
|---|---|---|

| 12:00 | 读取创作者中心数据 → 生成日报 → 飞书文档 + 摘要消息 → 写入知识库 | `workflow/daily/report.py` |
| 14:00–16:00 | 学习：搜索同类视频、拆解开头和节奏 → 学习笔记 → 写入知识库，更新「钩子想法」和「热词」清单 | `workflow/learn/session.py` |
| 22:00 + 随机 0–30 分钟 | 刷新热词 → 打开填好的抖音发布页 → 飞书通知「现在可以发布了」→ 用户检查后点发布 | `workflow/daily/publish_at.py` |
| 周六 18:00 | 周报 PPT → 飞书发文件和摘要 → 写入知识库 | `workflow/weekly/deck.py` |

时间错开：12:00 和 22:00 两个任务都要用发布台的登录 profile，不会同时占用；学习用另一个独立的 profile。详见 [[profile独占锁]]。

## 实施步骤（按优先级）

### 第 1 步：cc-piano 视频改造

1. **竖屏 1080×1920**：在 `tracks/daw.py` 加竖屏布局。上方是标题和封面，中间是多轨面板（轨道数可减少或放大），下方是歌词带和 Claude Code 小人。`build.py` 加 `vertical` 选项，`job.json` 按实际方向写 `orientation`。`tracks/flick_intro.py` 已经支持竖屏，直接复用。详见 [[竖屏短视频改造]]。
2. **前 3 秒钩子**（都做成模板参数，默认值保持旧行为）：`cold_open` 开头直接从副歌切入（复用 `lyrics.choose_window` 的副歌识别）；`intro` 时长可设为 0–4 秒，或把拨片动画移到副歌之后；`fade_in` 设为 0，第一帧就有声音；`hook_text` 第 0–3 秒的大字钩子文案；水墨转场时长可调。详见 [[前3秒钩子设计]]。
3. **iPhone 录屏直接导入**：`server.py:45` 的 `track_audio` 加上 `.mp4/.mov`；`prepare.py` 的 ffmpeg 步骤加 `-vn` 只取音频。新增本地收件箱 `douyin/收件箱/`：`produce.py` 每天用 `lark-cli im +chat-messages-list` 找出「抖音运营」群里新的视频或音频消息，用 `+messages-resources-download` 下载到这里。处理过的 message_id 记在 `workflow/data/inbox_seen.json`，不会重复处理；处理完在群里回复「已收到，开始制作《曲名》」。详见 [[concepts/收件箱与消息去重]]。
   - **前提**：机器人现在没有读群消息的权限（实测报 230027）。解决办法是用户重新登录一次 lark-cli 的个人身份，勾选群消息读取权限（`im:message.group_msg:get_as_user`），之后用用户身份读群消息；也可以在开发者后台给机器人加「获取群组中所有消息」权限。详见 [[机器人能否读取抖音运营群消息]]。
   - 收件箱里的录屏会被识别曲名（复用 `tracks/cache_identify.py` 和 `tracks/song_ocr.py` 抽一帧做 OCR），然后生成歌曲 json。
4. **60 秒卡点截取**（`tracks/prepare.py`、`tracks/lyrics.py`、`tracks/analyze.py`）：先去掉录屏首尾的静音和播放器的杂音；在整段音频上做节拍检测（复用 `analyze.py:67` 的 `librosa.beat.beat_track`，沿用 `daw.py:94` 对 140 BPM 以上的减半处理），再根据起音强度估出小节的第一拍（重拍）；选片段时 `lyrics.choose_window` 加 `target` 参数（55–65 秒，默认仍是原来的 95–106 秒），打分不变（副歌优先、句子不截断），没有歌词时选最响、最密的一段；片段起点和终点都吸附到最近的重拍；淡入淡出各约 1 拍，卡在节拍上（`build.py:274` 现在固定淡入 1 秒，改成模板参数 `fade_in_beats` / `fade_out_beats`）。详见 [[卡点截取与节拍吸附]]。
5. **画面随节拍动、开头和转场卡点**（`tracks/daw.py`、`tracks/stage.py`、`tracks/flick_intro.py`）：新增 `stage.BeatPulse`，重拍时整体画面轻微推近再回弹（约 1–2%），播放头和当前轨道闪一下，轨道波形随拍子亮一下，强度做成模板参数；拨片开头的总时长取整数个小节，最后一张卡片落定正好在重拍上；水墨转场（`daw.ENTRY`）的开始和结束也对齐节拍；歌词出现时间保持不变。小人跳舞、烟花本来就跟着节拍（`stage.py:349`、`stage.py:35`），保留。详见 [[concepts/beatpulse画面律动]]。
6. **模板库（带版本）**：新增 `tracks/templates/<模板名>/v<N>.json`，只存「怎么做」（主题、效果、竖屏、钩子参数、片段长度等）。歌曲 json 只存「做哪首」（音频、LRC、标题、发布信息），通过 `"template": "daw-classic@v1"` 引用模板，歌曲自己的字段优先。现有效果整理成 `daw-classic@v1`，保证旧歌出片完全一样（回归测试）；每次实验优化存成新版本（v2、v3……），旧版本永远不覆盖；音轨剪辑页加「模板」下拉框、「另存为新版本」、「用这个模板批量生成」（选多首歌，进同一个任务队列）。详见 [[模板库版本化]]。
7. **发布台**：音轨类成片走竖屏，抖音用 `video_vertical.mp4`；只发抖音。

### 第 2 步：飞书通知 + 每日制作和发布

1. `workflow/notify.py`：封装 lark-cli（直接调用 exe；文件参数要先 cd 到文件所在目录，按 CLAUDE.md 约定），提供三个功能：发文本或卡片、上传文件（视频、PPT）、新建文档。「抖音运营」群已经建好（机器人是管理员，用户是群主），测试消息已发出。以后所有通知、报表、PPT 都发到这个群，录屏也从这个群里收。如果用户以后要把内容转到「The First Step」外部群，就在群里手动转发。
2. `produce.py`：取收件箱里最早的一首；收件箱空了，就列出剪映缓存里最新的 3 首热曲（`jianying_cache()` 的逻辑）发飞书让用户选，用户回复之前不渲染；用「本周实验模板」渲染（复用 `tracks/build.py --prepare`）；渲染完把封面、标题、视频文件发到飞书供审核。
3. `publish_at.py`：22:00 启动，当天的随机发布时间写进日志（同一天只生成一次，重跑不重复）；到点先由 Claude 根据当天学到的热词改一版标题和话题（发布台本来就限制标题 ≤30 字、话题 ≤5 个）；然后调用 `publisher.py --job`（复用现有的 job 格式）打开 Edge，同时飞书通知「请在电脑上检查后点发布」；发布台检测到上传完成（状态 `ready`）再通知一次；出错时也通知。

### 第 3 步：数据读取 + 12:00 日报

1. `workflow/data/fetch_creator.py`：用 Playwright 打开 `publish/profile`（已登录），**只读**创作者中心的作品数据。翻页要慢，不做任何修改操作。数据存到 `workflow/data/daily/YYYY-MM-DD.json`，并追加到 `workflow/data/history.csv`；页面结构变了导致读不到时，标成「缺失」并在飞书提醒，**绝不编造数据**。
2. `report.py`：指标计算复用 `analytics/report.py`（`parse` 和指标函数）。Claude 按总方案的 9 段模板写日报，重点写完播率、2 秒跳出、前 3 秒，对照模板版本，提出 1–3 条「明天改什么」。生成飞书文档，私聊发一段摘要；同时把日报放进知识库的 `raw/sources/`，自动导入。

抓取字段清单：播放量、完播率、平均播放时长、2 秒跳出率、点赞、评论、分享、收藏、涨粉。

### 第 4 步：每日学习（14:00–16:00）

- 独立的 Playwright profile `workflow/learn/profile`（不登录），限时 2 小时，慢节奏访问。
- 搜索「Claude Code」「AI 编程」「音轨」「编曲」等关键词：记录热门视频的标题、时长、点赞和评论数、高赞评论。挑 3–5 条，下载后用 ffmpeg 抽取第 0、1、2、3 秒的画面和音频，用 [[faster-whisper]] 转写前 10 秒说的话，拆解开头的钩子、节奏和字幕。
- 顺便读一下抖音热榜，更新「热词清单」`workflow/learn/hotwords.json`。
- Claude 写学习笔记（`workflow/learn/notes/YYYY-MM-DD.md`）：哪些手法可以在我们的音轨模板里实现，哪些不适合。原则是不抄、不偏离主题。笔记写入知识库。
- 风险：不登录时，抖音网页版可能弹登录框或验证码。遇到就停下记录，退回到用搜索引擎找公开视频，并在日报里说明。

### 第 5 步：周报 PPT（周六 18:00）

- `ppt/weekly.js`（pptxgenjs，参考 `ppt/ai-news-2026-10-13.js` 的写法）：本周数据趋势图（完播率、播放、2 秒跳出）、各模板版本的对比、表现最好和最差的视频、学到了什么、下周实验方案。生成后用 pptx 技能的 `validate.py` 校验，再渲染成图片检查一遍。
- 通过飞书上传 .pptx（iPhone 上能直接打开），配一段摘要，同时写入知识库。

### 第 6 步：第一轮实验（10 月 26 日这一周）

- 基线：`daw-classic@v1`，只做横屏，用上周的数据。
- `daw-hook@v2` = v1 + 竖屏 + 开头直接进副歌 + 第一帧就有声音 + 0–3 秒钩子文字 + 缩短的拨片开头（结尾保留 Claude Code 小人和拨片元素）。
- 一次只改一个变量，每个变量持续 2–3 天，用完播率和 2 秒跳出率对比。实验记录 `workflow/experiments/round1.md`，同步到知识库。详见 [[单变量短视频实验设计]]。

### 第 7 步：上线

- 每个任务先手动跑通 2–3 次，再用 `schtasks` 挂成计划任务。
- 失败时飞书报警；每条日志记录开始、结束和结果；同一天、同一账号不重复推送。
- 更新 `D:\cc-engine\CLAUDE.md`：音轨剪辑页已不再保护、新增目录说明；更新 `douyin/README.md`：模板库、竖屏和收件箱的用法。

## 验证清单

- **截取和卡点**：用一段真实录屏出片，检查成片在 55–65 秒之间；起点和终点与重拍的偏差小于 50 毫秒（用检测到的节拍时间核对）；淡入淡出没有爆音；抽帧确认推近效果出现在重拍上。
- **视频**：用 `unhappy.json` 分别以 `daw-classic@v1` 和旧代码出片，逐帧对比，确认旧模板的结果不变；`daw-hook@v2` 出竖屏 10 秒预览，用 ffprobe 检查是 1080×1920，并抽第 0、1、3 秒的画面看钩子；用一段真实的 iPhone 录屏从收件箱走完整条流程。
- **飞书**：发测试消息和文件给用户，请用户确认 iPhone 收到推送。
- **数据**：手动跑 `fetch_creator.py`，和创作者中心页面上看到的数字逐条核对。
- **发布**：手动跑一次 `publish_at.py --now`，确认 Edge 打开、内容填好，飞书收到通知；**不替用户点发布**。
- **日报、周报**：各手动生成一份，用户看过满意后再挂定时。
- **知识库**：每类产出导入后，用 `llm_wiki_files` 和 `llm_wiki_read_file` 确认生成了页面。

## 不采用 iPhone 控制（调研结论，2026-10-24）

- [[witchan-ios-mcp]] 必须越狱（iOS 13–18），通过局域网 8090 端口连接，没有认证，还能执行任意 Shell 命令；`Lakr233/iphone-mcp`（Appium）和 `mirroir-mcp` 都需要 Mac。
- 越狱有安全风险，还可能触发抖音风控，危及账号。所以通知、收文件、学习都走飞书群和电脑端，不控制手机。详见 [[不控制iphone的决策依据]]。

## 需要用户配合的事项
