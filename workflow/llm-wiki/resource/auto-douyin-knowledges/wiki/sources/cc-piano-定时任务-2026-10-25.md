# cc-piano 定时任务（2026-10-25 开启）

## 概述

本来源记录 cc-piano 在 Windows 任务计划程序中新增的「cc-piano」任务文件夹（2026-10-25 开启），包含四个定时任务的时间表与职责，以及「定时调用 Claude 自动写评论故事」的实测成本、安全限制与两次失败教训。它属于运营自动化流程文档，是 [[cc-piano琴房-studio]] 运维层的配置记录，与既有 cc-piano 系列来源、抖音运营自动化方案高度衔接。

## 运行前提

任务文件夹只在**用户登录时运行**，因为发布环节要打开 Edge 窗口。日志位于 `workflow/logs/task_*.log`。这一约束使整套流程属于「自动化但非无人值守」，详见 [[定时任务编排与登录态依赖]] 与 [[windows计划任务]]。

## 四个定时任务

| 任务 | 时间 | 做什么 |
|---|---|---|
| daily-report | 每天 12:00 | 读创作者中心 → 日报发飞书群 + 存档 + 写知识库 |
| daily-make | 每天 14:00 | 收群里新录屏（和录屏后发的歌词）→ 认歌 → Claude Code 无界面模式读录屏评论区写评论故事、开头评论、标题文案话题 → 检查 → 用默认模板（daw@v6）出片 → 发群审核；没有新录屏就在群里提醒 |
| daily-publish | 每天 21:58 | 随机 22:00–22:29 打开抖音发布页填好，飞书提醒；用户自己点发布 |
| weekly-ppt | 每周六 18:00 | 周报 PPT 发群 |

各任务与既有概念的对应关系：

- **daily-report** 是 [[只读抓数与数据诚信]] 与 [[创作者中心只读抓数与日报规则]] 的定时化实例，数据源为 [[抖音创作者中心]]，投递渠道为 [[飞书]]。
- **daily-make** 把 [[评论区作为内容素材]] 与 [[评论故事动画]] 接入自动流水线，默认出片模板为 [[daw模板]] 的 daw@v6。
- **daily-publish** 是 [[发布台人工把关]] 在定时任务中的具体实现，操作对象为 [[抖音]] 发布页，时间窗设计见 [[随机化发布时间窗]]。
- **weekly-ppt** 对应 [[周报ppt自动化]]。

## 自动写评论故事

用户选择「定时调用 Claude 自动写」。每次约 1 分钟、约 0.5 美元（实测两次：0.48、0.51）。机制细节见 [[claude自动写评论故事]]。

### 安全限制（三重）

- Claude 只能用 Read / Write 工具；
- 只在 `workflow/data/story/<录屏名>/` 里工作；
- 不加载项目设置（hooks）和 MCP。

### 白名单校验

写出的 `story.json` 由 `daily_make.check_story` 按白名单检查：情绪、想象画面、音轨必须是认识的值，6~12 张卡片，长度有上限。不合格让 Claude 按错误修一次，还不行就不出片、在群里说。详见 [[生成结果白名单校验与一次修正]]。

## 两次实测失败与修复

1. **第一次没按格式写**（被检查拦下）→ 改成把模板文件放进文件夹、要求严格照抄结构，并加了一次修正机会。
2. **会抄错字**：把「兄弟到恋人这一步 我走了八年」写成「闺蜜……8年」→ 提示里要求逐字照抄、看不清的不要用，审核消息里也提醒用户对一下原话。详见 [[逐字照抄约束]] 与 [[claude抄错歌词原话]]。

## 证据强度与张力

- 四任务时间表与运行前提：配置性事实，直接来自任务计划程序设置，强。
- 成本数据：n=2（0.48、0.51），数值一致，可信度较高，但未说明是否含修正轮次开销。
- 两次失败：均为单次观察，因果链清晰但样本小。
- 模板版本：既有 [[daw模板]] 页面记录到 daw@v3，本来源称默认模板为 daw@v6，中间 v4/v5 缺失，需核实。
- 登录态依赖下若机器未登录或休眠，任务不执行，且本来源未说明失败告警机制，存在静默漏跑风险，见 [[定时任务漏跑如何告警]]。
