# cc-engine Workspace Conventions

## File locations
- All new files, scripts and outputs go in `D:\cc-engine`, organized by purpose (e.g. PPT work in `ppt/`). Do not put them on the C: drive.
- Temporary files (preview images, test data, intermediate results) go in `D:\cc-engine\.tmp\`, which can be cleared anytime. Do not use the C: temp folder or the session scratchpad.
- npm / pip dependencies install inside the project directory (e.g. `ppt/node_modules`), not globally.

## Diagram routing
Pick the tool by where the diagram ends up:
1. **Destination is Feishu/Lark** (a cloud doc, wiki page or whiteboard, new or existing): use Feishu's native drawing — `<whiteboard type="mermaid|svg|plantuml">` in `lark-cli docs +create/+update` (see `lark-doc` → `references/lark-doc-whiteboard.md`), or `lark-whiteboard` for existing boards. Do not insert a drawio PNG there unless the user asks for drawio.
2. **Everything else (default)**: use `drawio-skill` and produce an editable `.drawio` (export PNG/SVG as needed).
   - If the `drawio-skill` MCP server (project `.mcp.json`) is approved and connected, call its `mcp__drawio-skill__*` tools for build/sync/views/query/test/review/whatif/story.
   - If MCP is not allowed or not connected, run the skill's scripts directly (`python .claude\skills\drawio-skill\scripts\diagramctl.py ...`). The MCP server never exports PNG; export with the draw.io CLI.
3. Sending a finished drawio image into a Feishu chat or drive (not a doc) is fine: upload the PNG and `.drawio` with `lark-cli im` / `drive +upload`.
